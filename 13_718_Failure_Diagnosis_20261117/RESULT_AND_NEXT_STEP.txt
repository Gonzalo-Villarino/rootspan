The current V2 run found seven root candidates, produced two provisional lengths and withheld five lengths. Root 1 was withheld because its transition candidate and automatic endpoint conflict. The app now displays Gonzalo's 0 µm separately under Your reference; the automatic estimate remains a dash in the GUI and an empty cell in the CSV. In model columns these mean the pipeline could not report a supported length. They do not mean zero. A dash in Your reference means no reference has been recorded.

Why this matters
Our workflow must allow a root with no periderm. Periderm-like tissue in the adjacent hypocotyl must not be counted as root periderm. It also must not automatically turn every missing transition into a zero: a missing transition can reflect poor imaging, a detection failure, or a root segment containing periderm throughout.

What was checked
The complained-about run reproduced the previous V2 table exactly. This was not a browser or upload problem. As a diagnostic, we also ran the published four-class PAT weights on 7_18 without training. The raw output labels much of root 1's narrow main-root region as Endoderm and the swollen right-hand region as Periderm. Gonzalo supplied the anatomical interpretation of these regions. PAT has Background, Periderm, Endoderm and Lateral root classes, but no separate hypocotyl class.

This diagnostic uses the published weights with the local 1024-pixel tiling implementation (64-pixel halo, 896-pixel stride). It is not an exact reproduction of the original PAT stitching procedure. The class fractions in diagnosis.json are descriptive model outputs on an unverified centerline, not accuracy measurements or proof of periderm absence. No replacement model was released.

What changed today
The local app and exported CSV can retain an expert reference alongside the unchanged automatic result. Root 1's zero is bound to this exact source-image hash, V2 version, track ID, detection bbox, predicted T and automatic endpoint; the binding does not include every centerline coordinate. No training occurred; no model has learned this correction merely because it was recorded. Other roots have no new reference values.

The CSV keeps periderm_length_um as the automatic estimate and adds expert_periderm_length_um, expert_reference_status, expert_reference_id and expert_reference_author when a matching expert reference exists. The historical run CSV and job file are preserved; the download adds the reference columns. Conflicting or unreadable reference files produce a specific error instead of silently choosing a value. The app remains a learning prototype. This is a recording/display correction, not a successful model repair or V3 release.

Verification
The computational test results are saved in verification.json and unit_tests.txt. The live API and CSV returned expert zero separately from the blank automatic value; automatic counts stayed at two. Withdrawn-experiment warnings and the empty start page were retained. Source-image, historical run and published-weight hashes were unchanged. The locked V1 bundle (40 read-only files), V2 and archived V2.1 runtime fingerprints were verified. These software checks do not validate biological accuracy. See verification.json and ROOT1_REFERENCE_IN_GUI.png.

Next scientific step
Before another model is promoted, define reference examples for (1) periderm present, (2) periderm absent, and (3) uncertain, with the main root separated from hypocotyl and lateral roots. Root 1 is now one absence example and an approximate junction guide. More independently reviewed examples are needed to test whether an automatic absence decision generalizes. The approximate junction guide would need finer review before being used as an exact training or evaluation coordinate.

Use confirmed examples to develop an absence/junction decision, and evaluate it on different slides that have not been used to adjust the method. Do not hardcode root 1's zero, simply lower a threshold, or assume that the current examples prove accuracy. Because 7_18 has now been inspected during debugging, it is a development example, not an untouched final test. A new version should be promoted only if it improves the held-out comparisons without creating false zero lengths on roots that contain periderm.
